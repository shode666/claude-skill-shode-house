# 3.16 entrypoint consolidation

Scope: portable preview and targeted legacy entrypoint audit. This is a design
record, not task status; implementation is tracked in Beads shode-house-5cs.18.
Legacy callers remain unchanged until their migration is validated. The portable
folder does not load or replace installed legacy commands automatically.

## Ownership in the portable preview

One discoverable skill, `shode-house-team`, selects an outcome from the user's
request. Four internal references own conditional guidance; they are not additional
skills or slash commands. This avoids overlapping discovery descriptions.

| Existing entrypoints inspected | Ambiguity / overlap | Portable decision |
|---|---|---|
| `skills/workflow/dev-gate` + `skills/workflow/automate-test` | Both prescribe test gates; feature-level discipline and project CI setup can be conflated | One `verification.md` owns test quality. CI strategy is conditional, not a prerequisite for each feature; no universal test ratio |
| `commands/review.md` + `skills/workflow/diagnose` | Review accepts bug descriptions; diagnose triggers on bug words and includes fixing | Preserve distinct outcomes: review evaluates existing work, diagnosis explains cause, fix requires implementation authority; share verification guidance |
| `commands/design-system.md` | Name suggests UI tokens/components but description invokes a broader Smart Spec pipeline | In preview, request spec/architecture or UI design explicitly in natural language; do not advertise this legacy name as a portable alias |
| `skills/workflow/meeting` + `shode-house-routing` + `shode-house-workflow` | Meeting is actually a team entrypoint, with routing and phase indexes repeated across files | One core owns team selection and responsibility boundaries; no meeting recital or phase catalog required |
| `commands/consult.md` vs team engagement | A quick question may dispatch a named agent even when ordinary inspection is enough | Consult is an outcome, not compulsory delegation; invoke an expert only when it can change the next action |

Source paths above are repository-relative legacy directories/files. Examples are
not an exhaustive audit of every specialist skill, hook or command branch.

## Compatibility changes

### First compatibility slice: review and diagnosis

Existing names and paths remain callable. `/review` now delegates report storage
and posting authority to `review-checklist/report-format.md` instead of copying a
Beads-first storage script. Intake accepts explicit file/snippet scope without git
or tracker prerequisites. Supplying a Jira/PR reference no longer instructs automatic
posting. Project-authorized task tracking is still honored.

`diagnose` now ends with a cause/confidence report for diagnosis-only requests;
fix/regression steps require implementation authority. Test-gap follow-up distinguishes
a single regression test from project-wide CI strategy. The advanced loop reference
is conditional on permitted reproduction, not a prerequisite for tentative analysis.

This is not a complete migration of legacy orchestration: forced multi-agent review
and global legacy policy still require end-to-end host validation. Subsequent slices
below address test-gate and entrypoint duplication. No legacy command was removed.

### Meeting and design-system entrypoint slice

`meeting` is now a compatibility router, not a second team/phase catalog. Routing
owns roles/RACI; workflow owns engagement modes and phases; discipline owns legacy
safety and presentation. Removed duplicate tables and the unsupported claim that
line-count reduction proves 86% token savings. Existing names and paths remain.

`/design-system` retains its legacy name rather than adding a competing `/spec`
command (the repository discourages new commands for already-covered outcomes).
Its entry selection now distinguishes feature-spec authoring, bounded UI design,
and read-only advice/review. UI-only work exits without the full spec pipeline.
`--stop` does not imply estimation or authorize edits to a review target. Parsing
instructions preserve quoted content instead of executing/stripping shell arguments.

This improves outcome selection, not universal host support. Legacy phase rules
inside the full specification path have not been replaced by the portable workflow.

### Distinct responsibilities retained

- Review, diagnose and fix have different mutation authority even when they inspect
  the same code. One shared evidence reference does not merge their permissions.
- Code and spec review retain distinct responsibility, but share a finding when
  evidence concerns both axes.
- Security, migration and incident response have materially different risks; do not
  flatten them into a generic checklist merely to reduce entrypoint count.
- Legacy compatibility and the portable preview are separate distributions. Removing
  a legacy file requires inspecting agent preloads, command callers, registry and
  packaging checks together, not just removing a duplicate-looking name.

## Measurement boundary

### Test-gate compatibility slice

`dev-gate` owns per-change behavior tests and application-layer design checks;
`automate-test` owns project-wide CI strategy and wiring. Existing names stay intact
because their outcomes differ; merging discovery entrypoints would blur scope.
Removed duplicated fixed ratios/thresholds and mandatory hook installation from these
skills and aligned direct Chris/Quinn/Aaron guidance. Project-configured gates remain
authoritative. Init no longer invokes CI setup unconditionally. The historical
pre-commit example is optional and requires version/config verification before use.

Full legacy host validation remains separate from these source-level changes.

Core size is a loading-cost proxy, not actual token usage. Full-context work can
load more text than before because the new playbooks add engineering guidance.
Compare complete successful runs (including tests, rework, delegation and resume),
not only entrypoint bytes. Host parity and recovery remain separate acceptance tests.
