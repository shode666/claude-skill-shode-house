## Architecture boundary — revised: instruction-only default

The user selected a script-free operating path. The initial implementation is
the repository skill `.agents/skills/ask/SKILL.md`. It uses host tools
and project storage directly; no custom runtime, Python, Bash, jq, hooks or Beads
installation is required by the skill. Project build/test prerequisites still apply.
Build, lint, measurement and packaging scripts remain developer tooling.
Host metadata lives under `release/hosts/`: Codex UI YAML and the Claude plugin
manifest template. Packaging adds only the appropriate host configuration around
the shared six-file instruction payload. Native user model/permission settings
and project rules are not shipped or overwritten. There is no custom native agent
roster: optional expert delegation uses host capabilities, with Oliver in main.

Legacy scripts and the Claude plugin are retained pending a caller/dependency audit.
They are not implicitly loaded by the portable skill. `make pack-legacy` produces
the old package with hooks/output-style instructions; it is NOT the script-free
distribution. `make pack` uses the exact allowlist in `release/3.16.json` to build
the new RC from one source. Do not activate the legacy plugin alongside it and
expect its injected rules to disappear. This skill cannot override host instructions.

One shared contract owns capabilities, responsibilities, risk/applicability,
handoff, evidence validity and state transitions. Platform adapters translate
discovery, tools, identity, approvals, lifecycle and telemetry. They do not copy
business rules or invent host capabilities. Prefer host facilities over new wrappers.
Probe each host before declaring
native, hook, wrapper, advisory or unsupported enforcement. Skill discovery,
workflow execution and guard enforcement are separate acceptance results.

## Engineering workflow

`ask` is the only released entrypoint. Oliver owns the main session; consult,
design, implementation and review are internal outcomes. Explicit implementation
approval continues an identified design without another command. Initial source-
of-truth confirmation is required; later sessions reuse the recorded mapping.

The portable skill keeps ownership and routing in its core; conditional verification,
design review, decisions and continuity live in references inside the same folder.
Install the whole folder and load only relevant references. Review, diagnosis and
implementation remain different authorization scopes even when sharing evidence
guidance. See [entrypoint consolidation](3.16-entrypoint-audit.md) for the targeted
legacy overlap audit and migration boundaries.

Source of truth is project-selected: Markdown, Jira, Redmine, Beads or another
system. Resolve authority per concern rather than making every system authoritative
for everything. Keep canonical IDs and links; inaccessible remote tracking permits
a clearly marked pending handoff, not an unannounced replacement tracker. Reconcile
against current remote state before synchronizing an authorized update.

Each work unit has an outcome, acceptance criteria, delivery owner, independent
reviewer where needed, scope, dependencies, evidence paths and stop conditions.
Roles are capabilities, not a mandatory fan-out count. Small/standard/high-risk
paths select applicable checks; money/auth/PII retain independent specialist
review. Share evidence tied to the same source snapshot and environment;
re-execute when stale, disputed or independently required. Deduplicate findings
while preserving every review axis and dissent. Re-review affected dependencies.

Long runs route uncertainty by evidence, impact, reversibility and authority:
inspect facts first, consult an expert for bounded technical/domain judgment, and
ask the user for intent, business tradeoffs or authority beyond the agreed scope.
Continue independent work while a decision is pending; record decisions so resume
does not ask them again. Expert agreement and user silence never grant approval.

Verification includes overengineering: prefer application-layer solutions and
existing project facilities; justify new abstractions and infrastructure by a
current need. Apply SRP by cohesive responsibility/reason to change, not by class
counts. Keep necessary reliability/security boundaries. Code review owns design
proportionality; spec review links scope violations rather than duplicating them.

## Long-run acceptance

A checkpoint records the work/run identity, phase, completed artifacts and their
hashes, pending work, approvals, scope ownership, attempts, budgets and external
operation keys. Recover after process death, context compaction and host restart
without depending on remembered conversation. Reconcile durable state with actual
artifacts before proceeding; invalidate stale evidence and approvals.

The portable path tests checkpoints, stale evidence and resume using host facilities.
Custom reservation/journal tests below apply only to optional runtime integrations,
not as a prerequisite for using the team.

Crash tests cover before reservation, after reservation, after the external side
effect but before acknowledgement, and after acknowledgement. UNKNOWN operations
require reconciliation; never blindly replay an irreversible operation. Claim
exactly-once effects only where the downstream system supplies that guarantee.
Retries are bounded with backoff and a progress check. Exhausted budgets produce
a resumable checkpoint and explicit status, not a false completion. Persisted
state alone does not guarantee autonomous execution while the host is offline.

## Measurement and release evidence

Compare fixed fixtures/settings per host using at least three independent runs.
Measure whole-workflow input/cache-write/cache-read/output, main and child work,
retry/recovery overhead, wall latency, successful completion, false PASS, rework
and recovery success. Sum work across resumed sessions under the same run ID;
parallel invocation durations are not wall-clock latency. Keep failed attempts
in the cost accounting rather than selecting only successful cheap runs.

Bind evidence to source commit plus dirty-tree fingerprint, fixture, platform,
model/settings and collector version. Baseline and candidate must be distinct,
comparable observations. Missing records are UNSCORABLE. Historical scores prove
historical behavior, not the current candidate. Token-volume metrics are not
monetary cost; price/caching semantics must be normalized by each collector.

## Usage comparator boundary

`scripts/usage-report.py --compare BASELINE CANDIDATE` expects
`<root>/<scenario>/**/*.json`, one validated usage record per invocation or
non-overlapping invocation aggregate. `run_id` groups all work in one independent
workflow trial, including retries/resumes. At least three distinct run IDs per
scenario are required; scenario sets must match.

The legacy effective metric excludes cache reads for historical compatibility.
The new token-volume metric includes all four disjoint token buckets. Both have
median +3% / p90 +5% regression limits; component deltas are reported separately.
Quality, provenance, completion and latency gates remain separate requirements.
Claude/Cowork collectors now emit explicitly identified partial observations, not
benchmark-ready records; native completion/resume aggregation remains unverified.
Codex has a separate completed-stream collector. Do not forge multiple run IDs
from multiple agents to satisfy the minimum sample count.
