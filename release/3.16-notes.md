# 3.16.0 — Ask Oliver

Stable instruction-only workflow. Release qualification targets Codex; the Claude
package is configuration-compatible but runtime-unverified (experimental).

## What ships

- One `ask` entrypoint. Oliver owns the main session; experts are optional helpers,
  not a mandatory team or a custom native agent roster.
- Six shared Markdown instruction files: scope/ownership plus continuity,
  decisions, delivery, design review and verification references loaded on demand.
- Project-selected sources of truth with Markdown fallback, scoped authorization,
  evidence-aware resume and no blind replay of UNKNOWN external operations.
- Proportional application-layer/SRP guidance, independent expected test results
  and no speculative abstraction or duplicate review ceremony.
- Codex UI metadata; an experimental Claude manifest around identical instruction
  bytes. No runtime scripts, hooks, interpreter or tracker installation required.

## Install

Download `shode-house-v3.16.0-portable.zip` for Codex, extract `ask/` and copy it
into your project's `.agents/skills/`. Keep `references/` and `agents/openai.yaml`.
For Claude, the optional `shode-house-v3.16.0-claude.plugin` asset is a ZIP:
extract it into a new folder and load that folder through Claude's plugin mechanism.
Its entrypoint is `/shode-house:ask`. Do not install both project-skill and plugin
copies in the same host. Preserve existing model/security settings and project rules.

Do not install the repository root as the new plugin: it retains the legacy runtime.
Disable the legacy Shode plugin before testing the new skill in a fresh session.
Do not remove unrelated security controls. The automatic GitHub source archives
also include legacy source; use the named release assets above for installation.

[Installation and host configuration](https://github.com/shode666/claude-skill-shode-house/blob/v3.16.0/docs/portable-team-install.md)

## Acceptance and limitations

The release decision follows the user's request to prioritize a clear shared
rules/roles/knowledge-reference/workflow contract and authorization to publish.
Stable does not promise identical model outputs or deterministic enforcement.

Scoped Codex tests pass: review without edits, bounded changes, first-use mapping,
missing-reference disclosure, independent test expectations, fresh-session resume,
manual native compaction detecting stale PASS, and preserving a concurrent inline
annotation. Six instruction files are unchanged from tested source `e8f31da`.
Current packaging/configuration checks pass in normal and optimized Python modes;
Codex UI metadata is statically validated, not separately live-host certified.

**Release exception: combined token gates still FAIL.** In the RC9 matched trials,
median total volume decreased 18.23% for review and 4.52% for resume; uncached input
plus output increased 49.09% and 10.20%. We accept that limitation for promotion;
the original thresholds and FAIL evidence are not changed or represented as PASS.
No general token or monetary savings claim is made.

Claude runtime parity, Cursor and Antigravity acceptance remain unverified. Roles
and engineering references are provided, not the legacy 19-agent/domain knowledge
library. Models must consult project/domain evidence and escalate uncertainty.
Manual compaction and an inline-comment race do not prove arbitrary concurrent
merging, enforced locks, atomic checkpoints, multi-day uptime or exactly-once effects.
